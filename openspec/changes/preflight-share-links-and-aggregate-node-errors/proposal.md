# Proposal: 分享链接参数预检与节点错误聚合

状态：`archived`

## 问题

来源识别当前只根据 URI 协议判断 `formatReadyForCompilation`。因此 VLESS 链接即使包含重复参数、冲突别名、未知参数或不兼容 transport/security 选项，也会先显示“可转换并编译”，直到用户点击生成才失败。

严格编译器同时采用 fail-fast：每次只返回第一个节点的第一个问题。修复或兼容该字段后，下一个节点问题才会出现；多个不同原因又共用“尚未安全映射的分享参数”文案，造成同一来源需要反复生成和修改。

## 目标

1. 来源检查阶段复用权威 VLESS 转换器进行参数级预检，不复制第二套参数白名单；
2. 参数预检失败时设置 `formatReadyForCompilation=false`，并通过既有安全警告给出节点位置和问题类别；
3. 严格编译一次收集同一 URI 来源内的全部节点问题，返回有上限的安全摘要，不再只暴露第一个阻塞；
4. 区分未知分享参数、重复参数、冲突别名、security 选项和 transport 选项；
5. 错误与摘要不得包含 URI、节点名称、server、UUID、参数名或参数值；
6. 域名 bootstrap 仍是独立的严格隐私边界，不因参数预检而自动解析或降级。

## 验收场景

### 添加含多个不兼容节点的来源

- **GIVEN** 一个 VLESS URI 列表中的多个节点分别包含未知参数和不兼容 transport 选项
- **WHEN** 检查订阅或直接节点文本
- **THEN** 来源仍显示安全的节点/协议统计
- **AND** `formatReadyForCompilation=false`
- **AND** 警告一次列出有上限的节点位置和问题类别。

### 编译时来源内容发生变化

- **GIVEN** 来源检查后订阅响应发生变化并新增多个不兼容节点
- **WHEN** 用户执行严格编译
- **THEN** 编译器重新预检真实响应
- **AND** 一次返回多个节点问题而不是逐次暴露。

### 安全错误边界

- **GIVEN** 未知查询键和查询值包含秘密文本
- **WHEN** 预检失败
- **THEN** 错误只包含来源序号、节点序号、稳定问题类别和剩余问题数
- **AND** 不包含未知键、值或完整链接。
