# Proposal: 将 VLESS 转换器拆为独立功能入口

状态：`archived`

## 问题

已实现的 VLESS 分享链接转换器虽然使用独立 IPC，但界面入口、输入状态和结果展示仍嵌在配置生成流程的“直接粘贴节点”卡片中。用户明确要求它是一个独立功能，而不是现有节点来源功能的附属操作。

## 目标

1. 在应用顶栏提供两个一级功能入口：“配置生成”和“节点转换”；
2. “节点转换”进入独立页面，拥有自己的说明、输入、转换状态、错误和敏感 YAML 结果；
3. 从“直接粘贴节点”卡片移除转换按钮、转换结果及其状态，只保留“识别并添加”；
4. 独立页面继续复用 `convert_vless_node_text` IPC 和权威 VLESS 字段映射，不复制后端转换逻辑；
5. 切换一级入口时保留配置生成工作区状态；离开转换页时销毁转换页的 secret-bearing React 状态；
6. 结果继续默认折叠，明确说明只是 `proxies:` 片段，不代表导入、连接或出口验证。

## 交互决策

顶栏一级切换最符合“独立功能入口”：用户在进入三步配置工作流之前即可选择任务，不需要先理解“节点来源”与“识别并添加”。转换页不出现规则、bootstrap、草案或生成按钮，避免把一次性格式转换误解为配置编译步骤。

## 非目标

- 不新增窗口、多进程或路由依赖；
- 不改变 Rust IPC、VLESS 字段映射、去重或错误契约；
- 不把转换后的 YAML 自动加入配置生成来源；
- 不生成完整配置、文件或 Clash Verge 导入动作。

## 安全与回滚

- 转换输入和输出只存在于独立页面当前挂载期间、当前 IPC 与用户主动复制的剪贴板中；
- 切回“配置生成”会卸载转换页面并释放其 React 状态；
- 错误继续只显示稳定类别与节点位置，不回显分享链接秘密；
- 回滚副本：`/tmp/mihomo-studio-before-separate-vless-entry-20260820.tar.gz`；
- 当前目录没有 Git 元数据，不初始化仓库、不提交或推送。

## 验收场景

### 从顶栏进入转换器

- **WHEN** 用户点击一级入口“节点转换”
- **THEN** 主内容切换为独立转换页面
- **AND** 页面不显示配置生成的步骤 1/2/3、规则来源或 bootstrap 输入。

### 配置生成来源区

- **WHEN** 用户停留在“配置生成”
- **THEN** 直接节点编辑器只提供“识别并添加”
- **AND** 不显示“转换预览”或转换结果。

### 切换功能

- **GIVEN** 配置生成工作区已有来源或规则选择
- **WHEN** 用户进入转换器后再返回“配置生成”
- **THEN** 原配置生成状态保留
- **AND** 转换器输入不会混入直接节点来源。

## 证据边界

源码、测试、构建和本地界面验证只证明独立入口与转换契约；不证明 Clash Verge 已导入、节点已连接或最终出口有效。
