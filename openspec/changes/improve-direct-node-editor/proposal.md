# Proposal: 提升直接节点编辑区可读性

状态：`archived`

## 问题

“直接粘贴节点”当前与订阅链接并排显示，文本框只有一行高度。粘贴多个节点时，换行关系和当前内容规模都不清楚，长 URI 的软换行还会进一步混淆节点边界。

## 目标

- 让直接节点输入卡片占用完整内容宽度；
- 默认展示可检查多行内容的编辑高度，并允许用户继续纵向调整；
- 保留用户输入的真实换行，长 URI 不做软换行而是横向滚动；
- 显示非空行数量，并明确提示“一行一个节点”。

## 非目标

- 不改变节点解析、去重、指纹或 IPC 契约；
- 不增加秘密持久化、日志或错误回显；
- 不把浏览器预览伪装成已完成节点识别。

## 影响范围

- 主能力：`desktop-experience`；
- 实现：`src/features/source-inspection/`、`src/app/App.css`；
- 不涉及 Rust、Mihomo 配置生成、导出或 Clash Verge 加载。

## 安全、兼容与回滚

- 输入内容仍只保存在现有 React 页面状态中，不新增日志、缓存或持久化；
- 解析调用和数据契约保持不变；
- 回滚只需恢复 SourceSection 标记和对应样式/行数辅助函数。

## 验收场景

1. 打开步骤 1 时，直接节点卡片独占一行，编辑区默认可见 8 行；
2. 粘贴多个非空 URI 后，每个 URI 保持在独立视觉行，长 URI 可横向滚动；
3. 空行不计入“节点行数”，编辑区可纵向拖动调整；
4. 订阅探测、节点识别、来源列表和错误状态行为不变。

## 证据边界

- 源码与前端构建证明布局和交互门禁；
- 本变更不产生配置文件，不提供 Mihomo 验证、文件导出、外部加载、规则命中或最终出口证据。

## 完成证据

- 直接节点卡片与订阅卡片在 1280 px 视口中同为 620 px 完整内容宽度；
- 编辑区实测为 582 × 163 px，使用 `wrap=off`、`white-space: pre` 和纵向 resize；
- 长行实测产生横向溢出滚动，3 个非空输入行显示为“3 行”；
- 浏览器控制台无 warning/error；
- delta 已并入当前 `desktop-experience` Spec。
