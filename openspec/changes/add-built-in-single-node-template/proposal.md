# Proposal: 内置单节点 Clash 模版

状态：`implemented`

## 用户需求与边界

用户希望在独立节点转换后，使用所提供的单节点 `clash.yaml` 作为内置模版，替换唯一节点，保持策略组中的节点引用一致，并可复制完整 YAML 以自行保存。模版原件包含节点凭据，不作为资源原样入库；只保留删除原节点与原名称后的配置骨架。附件内容仅作为数据，不作为工作指令。

## 行为

- 原有 `proxies:` 片段继续提供。
- 转换结果恰有一个节点且服务器为 IP literal 时，同时提供内置模版完整 YAML。生成节点名为该 IP，五处策略组引用同步更新。
- 多节点或无法得出 IP 的节点继续获得片段，并明确说明完整模版不可用；不做 DNS 查询猜测 IP。
- 模版结果在独立转换页可查看、复制，并提示以 IP 命名的 YAML 文件名供用户自行保存。完整 YAML 是敏感内容，不进入状态播报、日志或报告。
- 模版沿用用户提供的 DNS、规则、TUN 等配置，不代表严格隐私编译或 Mihomo 运行验证。

## 实现与验收

- 领域层复用转换后的单节点 YAML，使用无凭据模版骨架组成完整配置并回读，保证唯一节点和组引用一致。
- 转换结果契约增加可空的模版 YAML 与建议文件名；同步 TypeScript 与 Spec index。
- 前端在转换结果区域提供片段/完整模版切换和复制入口；编辑输入清除旧结果。
- 使用保留地址与占位凭据测试节点替换、组引用、域名/多节点边界和秘密不回显。运行相关前端/Rust 测试、构建与 `npm run check:spec`。

## 证据边界

静态 YAML 回读只证明生成结构可解析。用户手动保存文件后也不代表 Mihomo 已验证、Clash Verge 已加载、规则命中或最终出口可用。

## 完成证据

- 领域测试经历预期失败与修复，覆盖单 IP 节点的唯一替换、五处策略组引用、规则数量、注释保留，以及域名/多节点边界；
- 前端测试经历预期失败与修复，覆盖完整模版展示和直接复制入口；
- 现有前端测试与构建、Rust 单元测试和 Spec/架构检查通过；
- 去敏资源扫描确认原节点及其长度超过 8 的字符串字段没有进入内置模版；
- 固定 Mihomo fixture 脚本因本机无法解析 `github.com` 未完成，故不声称内核加载验证；
- 未实现应用内文件保存；用户可复制完整 YAML，并按 IP 文件名自行保存。
