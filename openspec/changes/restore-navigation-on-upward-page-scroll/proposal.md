# Proposal: 页面向上滚动时恢复步骤导航

状态：`superseded`

> 后续 `simplify-single-column-generation-flow` 删除左侧步骤导航，因此本变更不再进入最终界面。

## 问题

桌面布局中，只要右侧预览栏曾滚动到 `scrollTop > 1`，步骤计算就持续优先返回 `03`。之后用户在主页面向上滚动，即使已经回到模式或来源区段，左侧 active 序号仍被预览栏的旧滚动位置锁住。

## 目标

- 主页面滚动时按主页面区段重新计算 `01/02/03`；
- 右侧预览栏发生内部滚动时仍立即激活 `03`；
- 同一动画帧内以最后发生滚动的容器为准；
- 保持唯一 `aria-current="step"`。

## 非目标

- 不改变页面布局、锚点位置或预览栏固定操作区；
- 不改变编译、来源、秘密或 IPC 契约；
- 不持久化滚动状态。

## 验收场景

### 场景：到底后向上滚动

- **GIVEN** 页面已到底部并激活 `03`
- **AND** 右侧预览栏保留非零 `scrollTop`
- **WHEN** 用户向上滚动主页面
- **THEN** active 序号按当前主页面区段切回 `02` 或 `01`
- **AND** 预览栏旧 `scrollTop` 不再锁住 `03`。

### 场景：滚动预览栏

- **WHEN** 最近一次滚动来自右侧预览栏
- **THEN** active 序号为 `03`
- **AND** 随后的主页面滚动重新取得判定权。
