# Proposal: 固定预览操作并同步步骤导航

状态：`archived`

## 问题

- 右侧预览内容较长时，生成按钮会随内容滚出可视区域，用户需要先找到操作入口；
- 左侧步骤导航把“01 节点来源”永久标记为 active，页面滚动到模式、规则或预览区域时，序号状态不会同步。

## 目标

- 桌面三栏布局中把生成操作固定在预览栏底部，预览内容仍可独立滚动；
- 窄窗口保持正常文档流，按钮仍作为预览区最后一个主要操作；
- 根据页面滚动位置同步 01/02/03 active 状态；
- 滚动右侧预览栏时标记 03，点击导航仍能到达对应步骤。

## 非目标

- 不改变草案、严格编译、节点来源或 IPC 契约；
- 不改变生成状态语义、YAML 内容或秘密处理边界；
- 不增加持久化导航状态。

## 影响范围

- 主能力：`desktop-experience`；
- 实现：`src/app/App.tsx`、`src/app/App.css`、`src/app/useWorkspaceNavigation.ts`、`src/features/profile-preview/ui/PreviewPanel.tsx`；
- 不涉及 Rust、配置序列化、Mihomo 验证或文件导出。

## 安全、兼容与回滚

- 只读取元素位置和滚动位置，不读取或记录订阅、节点或 YAML 内容；
- 导航仍使用标准锚点，并增加 `aria-current`；
- 回滚只需移除滚动导航 hook、预览锚点和固定底部样式。

## 验收场景

1. 桌面宽度下，右侧预览内容滚动时生成按钮始终位于预览栏底部；
2. 页面从来源滚到模式、再滚到预览锚点时，左栏依次激活 01、02、03；
3. 桌面右侧预览栏发生内部滚动时激活 03；
4. 窄窗口中预览区按正常文档流展示，生成按钮位于该区内容底部；
5. 编译调用、错误状态与生成结果保持不变。

## 证据边界

- 单元测试证明步骤判定优先级；
- 前端构建和浏览器检查证明布局、滚动与 active 状态；
- 本变更不产生新的 Mihomo、导出、外部加载或出口证据。

## 完成证据

- `npm run check:spec` 通过：8 个能力、5 个 IPC 命令，架构检查覆盖 36 个 Rust 文件与 17 个前端文件；
- `npm test` 通过：3 个测试文件、12 个测试，其中步骤判定覆盖来源、模式、预览、页面底部与预览栏内部滚动；
- `npm run build` 通过；
- 1280 × 720 浏览器验证中，导航按 01 → 02 → 03 唯一激活，03 在页面到达底部时正确激活；
- 右侧预览栏从 `scrollTop = 0` 滚动到 `426.5` 后，生成按钮仍保持在预览栏可视底部（按钮底部 `695.77px`，面板底部 `719.77px`），控制台无 warning 或 error。
