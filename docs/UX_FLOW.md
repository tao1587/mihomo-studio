# UI 与交互规划

## 1. 交互原则

- 首页首先回答“节点有没有读到、规则有没有冲突、配置能不能导出”；
- 简单模式只展示用户意图，不展示底层 YAML 术语；
- 完全模式提供细节，但所有高级项都有默认值和影响说明；
- 每次修改都先形成预览，不直接改写外部应用；
- 秘密 URL 只显示来源名称和脱敏主机，不出现在通知、日志和错误详情；
- 把“配置已生成”和“Clash Verge 已加载/运行”明确区分。

## 2. 首次使用：三步向导

### 第一步：添加节点来源

页面中央只有三个大按钮：

- `添加订阅链接`
- `粘贴节点`
- `导入配置文件`

订阅卡片字段：

- 名称；
- URL（默认密码式遮罩）；
- 自动识别 / 指定 User-Agent；
- 节点名称前缀；
- 更新周期；
- 输出为 Provider / 快照 / 自动。

点击“测试”后只显示：

- 是否可访问；
- 识别格式；
- 节点数量；
- 协议分布；
- 使用了哪个解析适配器；
- 警告数量。

不回显完整响应或完整 URL。

### 第二步：选择模式和用途

顶部为两个并列卡片：

- **简单模式（推荐）**：日常上网、广告拦截、AI/Claude、流媒体、国内直连；
- **完全模式**：规则源、优先级、策略组、DNS/TUN、去重级别和输出方式全部可调。

简单模式的主要控件：

1. `基础广告拦截` 开关；
2. `Claude / AI` 策略下拉框；
3. `流媒体` 策略下拉框；
4. `国内流量` 默认 DIRECT；
5. `其他流量` 默认节点选择；
6. `GitHub 镜像` 可选输入框；
7. `国家分组` 自动生成开关。

### 第三步：检查并导出

顶部给出单一结论：

- 绿色：可以导出；
- 黄色：可以导出，但存在可解释警告；
- 红色：引用、循环或 Mihomo 校验失败，需要修正。

摘要卡片：

- 节点总数 / 去除重复数；
- 规则总数 / 去除重复数；
- 冲突数；
- 策略组数量；
- 来源更新时间；
- Mihomo 验证版本。

主要操作：

- `导出完整 YAML`
- `查看差异`
- `打开导出目录`
- `保存为模板`

首版对 Clash Verge Rev 的说明只有“一次导入这份 YAML”；后续再增加有备份、预览和回滚的受控同步。

## 3. 主界面信息架构

左侧导航：

1. **概览**：配置状态、上次生成、问题摘要；
2. **节点来源**：订阅、单节点、本地文件；
3. **规则与策略**：模式、规则目录、策略绑定；
4. **策略组**：可视化组关系和节点筛选；
5. **预览与导出**：YAML、差异、验证；
6. **设置**：GitHub 镜像、缓存、Mihomo 版本、隐私。

## 4. 完全模式的规则编辑

规则源使用卡片列表，不让用户先面对长表单。每张卡片显示：

- 来源名称和许可证；
- 维护状态；
- 规则格式；
- 默认策略；
- 优先级；
- 最近更新时间和内容 hash；
- 开关和拖拽排序。

展开卡片后才显示：

- canonical URL；
- effective fetch URL（脱敏）；
- 镜像覆盖；
- branch/ref/commit；
- 缓存和失败回退；
- 去重策略；
- 来源说明。

冲突视图不只是“删了多少条”，而是按以下方式解释：

- A 与 B 完全相同，保留 A；
- A 的 CIDR 包含 B，且目标相同，保留 A；
- A 与 B 匹配相同对象但目标不同，按优先级保留 A，并要求用户确认；
- `DOMAIN-KEYWORD` 可能覆盖更精确规则，仅提示，不默认自动删除。

## 5. 策略组编辑器

默认使用卡片和关系线，不要求手写正则：

- 组类型：选择、自动选择、故障转移、负载均衡；
- 来源：所有节点、指定订阅、指定国家、指定协议、其他策略组；
- 包含/排除关键词；
- 空组回退；
- 延迟检测地址和周期。

保存前执行：

- 空组检测；
- 重名检测；
- 悬空引用检测；
- 循环引用检测；
- UDP 能力提示；
- 组名和规则目标一致性检查。

## 6. 动态国家组

沿用 NAS 的“只为实际存在的国家生成策略组”思路，但改进为：

- 先 URL decode 和 Unicode 规范化节点名；
- 国家别名和旗帜由可版本化词典管理；
- 支持用户调整识别结果；
- 不生成空的国家组；
- 删除节点来源后重新编译，自动移除失效国家组；
- 对识别不确定的节点放入“未分类”，不静默误分。
