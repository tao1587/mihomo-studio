# 产品规划

## 1. 产品定位

Mihomo Studio 是一个本地优先的桌面配置编译器：把节点来源、规则来源、策略组意图和基础网络选项编译成一份完整、可审计、可验证的 Mihomo YAML。

它解决的不是“再做一个 Clash Verge”，而是以下问题：

- 订阅和单节点格式不一致，用户难以手工合并；
- 规则集多、格式不同、顺序敏感，直接拼接会重复或冲突；
- 策略组需要引用实际节点和其他组，手写容易形成空组、悬空引用或循环；
- ACL4SSR、Mihomo 原生规则、热门开源规则 family 和 Claude 专用规则缺少一个统一管理界面；
- 用户希望在 Clash Verge Rev 中只导入一份配置，而不是逐项添加规则、组和节点。

## 2. 首版范围

### 2.1 输入

- 订阅 URL；
- 一次粘贴一个或多个节点 URI；
- 本地 Mihomo/Clash YAML；
- 本地 Base64/URI 列表；
- 远程规则 URL；
- GitHub 仓库规则源；
- 用户自定义的置顶规则和兜底规则。

首批协议目标：

- VLESS（含 Reality、WebSocket、gRPC 等常见传输参数）；
- VMess；
- Trojan；
- Shadowsocks；
- Hysteria2；
- TUIC；
- WireGuard；
- SOCKS/HTTP。

最终协议支持以所绑定的 Mihomo 版本为准，不由 UI 静态宣称。

### 2.2 处理

- 多种 User-Agent 探测订阅响应；
- YAML、URI 列表、Base64 列表的内容识别；
- 节点名称解码、来源标签、重名消解；
- 动态国家/地区识别和策略组生成；
- 规则格式归一化；
- 精确去重、受约束的语义去重、冲突检测；
- 策略组引用完整性和循环检查；
- 规则顺序编译；
- Mihomo 配置验证；
- 生成报告和来源说明。

### 2.3 输出

- 一份完整的 Mihomo YAML；
- 一份不含秘密 URL 的生成报告 JSON；
- 一份人类可读的预览摘要；
- 可选的 last-known-good 回滚副本。

首版提供两种节点输出方式：

1. **快照模式**：把本次解析到的节点写入 `proxies`，稳定、便于审计；
2. **Provider 模式**：把兼容的订阅保留为 `proxy-providers`，由 Mihomo 定时刷新。

简单模式默认“自动”：先验证 Provider 是否可由 Mihomo 正确加载；不适配时退回快照模式，并在 UI 中显示原因。

## 3. 两种产品模式

### 3.1 简单模式

简单模式不展示原始 INI/YAML，也不要求用户理解 rule-provider。

用户只需选择：

- 节点来源；
- 日常上网、AI 优先或流媒体优先之一；
- 是否启用基础广告拦截；
- Claude/AI 走哪个策略；
- 国内直连、国外代理的默认行为；
- 是否使用 GitHub 镜像。

默认生成的策略组：

- `节点选择`：总入口；
- `自动选择`：所有可用节点的延迟优选；
- `故障转移`：失败后按顺序切换；
- 实际存在的国家/地区组；
- `AI / Claude`；
- `流媒体`；
- `广告拦截`；
- `其他兜底`。

默认规则层次：

1. 用户置顶规则；
2. 规则修正/直连例外；
3. 可选的精确遥测拦截；
4. 广告和隐私规则；
5. Claude/AI 等专用服务；
6. 流媒体和其他应用服务；
7. 国内域名/IP 直连；
8. 国外/代理规则；
9. 唯一 `MATCH,其他兜底`。

### 3.2 完全模式

完全模式开放：

- 规则源目录、远程地址、分支/commit 固定；
- GitHub 镜像的全局值和单源覆盖；
- 下载代理、请求头、更新周期、缓存策略；
- 规则源优先级和目标策略；
- 策略组类型、节点筛选、组引用、健康检查；
- 国家识别词典和正则；
- 精确/保守语义/激进去重级别；
- DNS、TUN、sniffer、IPv6、geodata；
- Claude 进程规则、UDP fail-closed 和精确遥测拦截；
- 自定义前置/后置规则；
- Provider/快照输出选择；
- 配置差异和来源追踪。

## 4. Claude 专用规则包

从 Claude Purge 当前受管规则中提取一个独立、版本化的“Claude 强化”规则包，但不复制 Claude Purge 的运行态所有权、回滚和系统改写逻辑。

规则包分为三层：

1. **Claude 路由（默认开启）**
   - 受约束的 Claude 进程名规则；
   - Anthropic/Claude 第一方域名；
   - Claude MCP 与内容域名。
2. **Claude UDP fail-closed（默认关闭）**
   - Mihomo 支持逻辑规则时，拒绝 Claude 规则集命中的 UDP；
   - 仅用于用户明确要求 Claude 固定走指定出口的场景。
3. **精确第三方遥测拦截（默认关闭）**
   - 只拦截经过核对的精确遥测主机；
   - 不把共享 GitHub、Cloudflare、Google、Stripe、hCaptcha 等基础设施做成宽泛拦截。

桌面进程规则在不支持进程识别的平台自动降级为域名规则，并明确显示降级状态。

## 5. 非目标

首版不做：

- 代理内核常驻托盘控制；
- 系统代理/TUN 开关；
- 机场管理或订阅销售；
- 云端保存用户订阅；
- 自动上传 Gist；
- 无预览地覆盖 Clash Verge Rev 配置目录；
- 执行第三方远程 JavaScript；
- 对规则命中效果做未经运行态验证的承诺。

## 6. 成功标准

- 3 步内从添加订阅到导出 YAML；
- 用户不手写 YAML 即可完成日常配置；
- 多来源节点不会因后导入 YAML 覆盖前一个来源；
- 所有策略组引用存在且无循环；
- 所有规则目标存在；
- 冲突规则不会被静默删除；
- 规则去重报告能追踪到来源；
- 最终只有一个 `MATCH` 且位于最后；
- 输出通过绑定版本的 Mihomo 配置验证；
- 订阅 URL/token 不出现在应用日志和生成报告中；
- macOS、Windows、Linux 使用同一套配置编译核心。
